Write a pull-request description for the current branch and worktree.

1. Read `AGENTS.md`, `docs/target-repo-primer.md`, `library/personas/release-steward.md`, `governance/policies/PR-001.json`, and `library/skills/write-pr-description.md`.
2. Treat `$ARGUMENTS` as at most one optional `--worktree <name>` selection plus at most one literal Git base ref. Use `main` when no base ref is given. Reject any other option, multiple base refs, shell syntax, or a ref that `git rev-parse --verify` cannot resolve to a commit.
3. When a worktree is named, run `./bin/pan worktree resolve <name> --json` to create or resolve it, and perform every Git resolution and comparison in the following steps inside the reported worktree path.
4. Run `./bin/pan pr-description context [--worktree <name>] --json`. Read each template and instruction path in the result.
5. Stop when the context command reports `PR_TEMPLATE_AMBIGUOUS` or another target-authority defect. Do not select a template yourself.
6. Resolve the current branch, the selected base ref, and their merge base. Compare all committed branch changes plus staged, unstaged, and relevant untracked worktree changes against that merge base. Do not compare only `HEAD` or only the unstaged diff.
7. Convert the current branch and base ref to filename-safe slugs by replacing every run of characters outside `[A-Za-z0-9._-]` with `-` and trimming leading or trailing `-`. Choose a unique harness-relative output path under `runtime/pr-descriptions/` named `<UTC timestamp>-<branch-slug>-against-<base-slug>.md`. In an embedded installation, write the corresponding file under `.pancreator/runtime/pr-descriptions/`.
8. Invoke the `pan-release-steward` subagent in standalone PR-writing mode with the selected base ref, output path, and resolved PR context. Inline the complete resolved `PR-001` policy and PR-description procedure into the delegated prompt; a path reference is not a substitute. Require it to inspect the actual Git delta, write no other file, and omit the delivery-pipeline manifest unless a workflow run was explicitly supplied.
9. Run `./bin/pan requirements run --persona release-steward --workflow standalone --stage write-pr --kind standalone --registry PR-DESCRIPTION-VALIDATE-001 --target <output-path> [--worktree <name>] --json` after the file is final. Stop when validation fails.
10. Stop without writing a description when there is no committed or worktree delta against the merge base, when the base cannot be resolved, or when the repository is in a detached or otherwise ambiguous state that prevents an accurate PR comparison.
11. Do not modify source, workflow state, release metadata, commits, branches, remotes, or pull requests. Do not run `gh pr create`, commit, push, merge, publish, or deploy.
12. Surface the selected base, merge base, output path, and the complete generated Markdown in one fenced `markdown` block. Do not replace the generated description with a summary.
