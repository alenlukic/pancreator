Write a pull-request description for the current branch and worktree.

1. Read `{{PANCREATOR_HARNESS_PATH}}AGENTS.md`. Then run `{{PANCREATOR_PAN_COMMAND}} governance card --mode write-pr` and read the card it writes in full. When a worktree is named, add `--worktree <name>` so the card creates or resolves it and binds the session workspace to it. The card is the complete resolved governance for this mode. Do not assemble policy text by hand and do not generate a second card for the same session.
2. Read `{{PANCREATOR_HARNESS_PATH}}docs/target-repo-primer.md`, `{{PANCREATOR_HARNESS_PATH}}library/personas/release-steward.md`, and `{{PANCREATOR_HARNESS_PATH}}library/skills/write-pr-description.md`.
3. Treat `$ARGUMENTS` as at most one optional `--worktree <name>` selection plus at most one literal Git base ref. Use `main` when no base ref is given. Reject any other option, multiple base refs, shell syntax, or a ref that `git rev-parse --verify` cannot resolve to a commit.
4. When the card reports a worktree, perform every Git resolution and comparison in the following steps inside the reported worktree path.
5. Run `{{PANCREATOR_PAN_COMMAND}} pr-description context [--worktree <name>] --json`. Read each template and instruction path in the result.
6. Stop when the context command reports `PR_TEMPLATE_AMBIGUOUS` or another target-authority defect. Do not select a template yourself.
7. Resolve the current branch, the selected base ref, and their merge base. Compare all committed branch changes plus staged, unstaged, and relevant untracked worktree changes against that merge base. Do not compare only `HEAD` or only the unstaged diff.
8. Convert the current branch and base ref to filename-safe slugs by replacing every run of characters outside `[A-Za-z0-9._-]` with `-` and trimming leading or trailing `-`. Choose a unique harness-relative output path under `{{PANCREATOR_HARNESS_PATH}}runtime/pr-descriptions/` named `<UTC timestamp>-<branch-slug>-against-<base-slug>.md`. In an embedded installation, write the corresponding file under `.pancreator/runtime/pr-descriptions/`.
9. Invoke the `pan-release-steward` subagent in standalone PR-writing mode with the selected base ref, output path, and resolved PR context. Paste the complete contents of the card file into the delegated prompt, followed by the PR-description procedure; a path reference, summary, or excerpt is not a substitute. Require it to inspect the actual Git delta, write no other file, and omit the delivery-pipeline manifest unless a workflow run was explicitly supplied.
10. Run `{{PANCREATOR_PAN_COMMAND}} requirements run --persona release-steward --workflow standalone --stage write-pr --kind standalone --registry PR-DESCRIPTION-VALIDATE-001 --target <output-path> [--worktree <name>] --json` after the file is final. Stop when validation fails.
11. Stop without writing a description when there is no committed or worktree delta against the merge base, when the base cannot be resolved, or when the repository is in a detached or otherwise ambiguous state that prevents an accurate PR comparison.
12. Do not modify source, workflow state, release metadata, commits, branches, remotes, or pull requests. Do not run `gh pr create`, commit, push, merge, publish, or deploy.
13. Surface the card path, the selected base, merge base, output path, and the complete generated Markdown in one fenced `markdown` block. Do not replace the generated description with a summary.
