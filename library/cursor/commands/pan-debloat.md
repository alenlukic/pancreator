Remove harness facilities nobody used, and land the removal as a minor release. Treat `$ARGUMENTS` as optional operator context plus an optional `--days <1..365>` window override, which defaults to 30.

1. Read `{{PANCREATOR_HARNESS_PATH}}AGENTS.md`. Read `{{PANCREATOR_HARNESS_PATH}}config.json` and stop without mutation unless `installation_mode` is `self_development`. This command does not remove facilities from an installed target payload.
2. Run `{{PANCREATOR_PAN_COMMAND}} list --json`. Stop if a mutating workflow is active against this workspace.
3. Create the session worktree from the default branch: `{{PANCREATOR_PAN_COMMAND}} worktree create <YYYYMMDD-HHMMSS>-debloat --from main --description 'Harness debloat session'`, using the current UTC date and time. Record the name; every later step names it.
4. Run `{{PANCREATOR_PAN_COMMAND}} governance card --mode debloat --worktree <name>` and read the card it writes in full. The card is the complete resolved governance for this mode. Do not assemble policy text by hand and do not generate a second card for the same session.
5. Run `{{PANCREATOR_PAN_COMMAND}} debloat scan --days <window> --worktree <name> --json`. Record the `session_id` and read the report it names. The scan mutates nothing.
6. Present the candidates to the operator grouped by category, with each category's confidence line from the report. State plainly that a `weak` or `medium` category rests on thinner evidence than a `strong` one. Also surface the counts from the report's "Idle but depended upon" section, so the operator can see what was withheld and why. Then stop and wait. The selection is the operator's decision, so do not choose on their behalf.
7. Record the operator's answer verbatim: `{{PANCREATOR_PAN_COMMAND}} debloat select --session <session-id> --facility <id>` once per chosen id. The command refuses an id the scan did not report as an unused candidate. Do not add an id the operator did not name.
8. Run `{{PANCREATOR_PAN_COMMAND}} debloat impact --session <session-id> --json` and read the closure manifest it names. Report the cascade to the operator when `cascaded` is non-empty, because it removes more than they selected.
9. Invoke the `pan-debloater` subagent. Paste the complete card into the delegated prompt, followed by the session id, the worktree path, and the complete contents of `closure.json`. Require it to adjudicate every removal against the manifest's three adjudication categories before deleting, to repair rather than delete every `edit` entry, and to run `{{PANCREATOR_PAN_COMMAND}} models --sync`, `npm{{PANCREATOR_NPM_PREFIX}} run typecheck`, `{{PANCREATOR_PAN_COMMAND}} repository-check configuration`, and `{{PANCREATOR_PAN_COMMAND}} repository-check full` inside the worktree.
10. Run `{{PANCREATOR_PAN_COMMAND}} debloat verify --session <session-id> --json`. It exits 1 while a listed path survives or a file still names a removed facility. Give the exact failures back to the debloater for one correction pass, then rerun it and the failed checks.
11. Allocate the release: `{{PANCREATOR_PAN_COMMAND}} release allocate --worktree <name> --bump minor --json`. A facility removal changes installable harness inputs, so it reaches `pan-dev` only inside a release.
12. Run the `/pan-release` flow for the same worktree to finish release preparation. It owns the release metadata, the two release commits, and the final PR copy. Do not edit release metadata yourself and do not skip its validation.
13. Land the branch. `{{PANCREATOR_PAN_COMMAND}} worktree reconcile` requires two or more sources and cannot merge a single branch, so check out `pan-dev` in its own checkout and merge with `git merge --no-ff <branch>`. Resolve conflicts in that checkout.
14. Do not push, open or merge a PR, publish, deploy, rewrite history, or delete the worktree branch. Surface the card path, the session directory, the removed facility list, the release commit, the index commit, and the remaining operator-owned remote actions.
