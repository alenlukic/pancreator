Prepare or regenerate Pancreator release metadata from the complete repository delta. Treat `$ARGUMENTS` as optional operator context plus one optional `--worktree <name>` selection. Never use the context as a substitute for inspecting Git history and the worktree.

1. Read `AGENTS.md`, `docs/target-repo-primer.md`, `library/personas/release-steward.md`, `governance/policies/VERSION-001.json`, and `library/skills/update-release-metadata.md`.
2. Read `config.json` and stop without mutation unless `installation_mode` is `self_development`. This command does not version embedded target repositories.
3. Run `./bin/pan list --json`. Stop if a mutating workflow is active against this workspace; the workflow ship stage owns its own automatic release update.
4. When the operator selects a worktree, run `./bin/pan worktree resolve <name> --json` to create or resolve it. Reject a missing name or more than one selection. That worktree checkout is then the repository the steward inspects, edits, and validates in the following steps.
5. Invoke the `pan-release-steward` subagent in standalone release-metadata mode. Inline the complete resolved `VERSION-001` policy and release-metadata procedure into the delegated prompt; a path reference is not a substitute. Require it to inspect the complete change range since the last committed release bump, select exactly `major`, `minor`, or `patch`, author or regenerate the current release notes, and synchronize all required version-bearing files.
6. Require idempotence: when an uncommitted candidate already exists, regenerate it in place rather than incrementing again. When there are no changes and no candidate, make no edits.
7. Permit edits only to `CHANGELOG.md`, `VERSION`, `package.json`, `package-lock.json`, `README.md`, and version-bearing Markdown under `docs/`. Never edit `release/index.json`.
8. Run `npm run format:check`, `npm run typecheck`, and `npm run validate`, inside the resolved worktree path when the operator named one. If validation fails, provide the exact failures to the release steward for one correction attempt and rerun the failed checks.
9. Do not commit, push, open or merge a PR, publish, deploy, rewrite history, or invent the future release commit hash.
10. Surface the baseline commit, selected bump, previous and proposed versions, changed release files, validation results, and the rendered latest changelog entry.
