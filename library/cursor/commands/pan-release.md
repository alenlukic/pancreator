Prepare or regenerate Pancreator release metadata from the complete repository delta. Treat `$ARGUMENTS` as optional operator context plus one optional `--worktree <name>` selection. Never use the context as a substitute for inspecting Git history and the worktree.

1. Read `{{PANCREATOR_HARNESS_PATH}}AGENTS.md`. Then run `{{PANCREATOR_PAN_COMMAND}} governance card --mode release` and read the card it writes in full. When the operator selects a worktree, add `--worktree <name>` so the card creates or resolves it and binds the session workspace to it. The card is the complete resolved governance for this mode. Do not assemble policy text by hand and do not generate a second card for the same session.
2. Read `{{PANCREATOR_HARNESS_PATH}}docs/target-repo-primer.md`, `{{PANCREATOR_HARNESS_PATH}}library/personas/release-steward.md`, and `{{PANCREATOR_HARNESS_PATH}}library/skills/update-release-metadata.md`.
3. Read `{{PANCREATOR_HARNESS_PATH}}config.json` and stop without mutation unless `installation_mode` is `self_development`. This command does not version embedded target repositories.
4. Run `{{PANCREATOR_PAN_COMMAND}} list --json`. Stop if a mutating workflow is active against this workspace; the workflow ship stage owns its own automatic release update.
5. When the card reports a worktree, that worktree checkout is the repository the steward inspects, edits, and validates in the following steps. Reject a missing name or more than one selection.
6. Invoke the `pan-release-steward` subagent in standalone release-metadata mode. Paste the complete contents of the card file into the delegated prompt, followed by the release-metadata procedure; a path reference, summary, or excerpt is not a substitute. Require it to inspect the complete change range since the last committed release bump, select exactly `major`, `minor`, or `patch`, author or regenerate the current release notes, and synchronize all required version-bearing files.
7. Require idempotence: when an uncommitted candidate already exists, regenerate it in place rather than incrementing again. When there are no changes and no candidate, make no edits.
8. Permit edits only to `CHANGELOG.md`, `VERSION`, `package.json`, `package-lock.json`, `README.md`, and version-bearing Markdown under `{{PANCREATOR_HARNESS_PATH}}docs/`. Never edit `release/index.json`.
9. Run `npm{{PANCREATOR_NPM_PREFIX}} run format:check`, `npm{{PANCREATOR_NPM_PREFIX}} run typecheck`, and `npm{{PANCREATOR_NPM_PREFIX}} run validate`, inside the resolved worktree path when the operator named one. If validation fails, provide the exact failures to the release steward for one correction attempt and rerun the failed checks.
10. Do not commit, push, open or merge a PR, publish, deploy, rewrite history, or invent the future release commit hash.
11. Surface the card path, the baseline commit, selected bump, previous and proposed versions, changed release files, validation results, and the rendered latest changelog entry.
