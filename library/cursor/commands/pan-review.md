Run one review-squad pass over the target named by `$ARGUMENTS`.

You coordinate the session in this conversation. There is no workflow run, no stage contract, and no gate. This command produces findings and a verdict; it authorizes no edit, no commit, and no push.

1. Read `{{PANCREATOR_HARNESS_PATH}}AGENTS.md`; preserve `$ARGUMENTS` verbatim in a uniquely named file under `{{PANCREATOR_HARNESS_PATH}}runtime/inbox/` as the review input. When `$ARGUMENTS` is empty, write the target you derive in step 3 into that file instead.
2. Run `{{PANCREATOR_PAN_COMMAND}} governance card --mode review --request <harness-relative-input>` and read the card it writes. It resolves the complete review governance, including `REVIEW-001` and its reference to the squad procedure. Read that reference. Do not assemble policy text by hand.
3. Resolve exactly one target. A ref range (`main...my-branch`), a single ref (compared against its merge base with the repository's default branch), a pull request number or URL, or an explicit path set are all valid. With no argument, use the current branch against its merge base with the default branch. State the resolved range before you capture it. Ask the operator when the request is ambiguous rather than absent.
4. Capture the target once to `review-target.diff` beside the card, using `git diff --merge-base` for a single ref or `git diff <base>...<head>` for a range. Confirm the capture is non-empty; an empty capture ends the session with that fact and no review.
5. Bind the workspace to the target's head before you delegate. The command reviews any ref from any checkout, but the reviewing agents read code to confirm what the diff only claims, so the tree they read MUST be the tree the diff applies to. Compare `git rev-parse HEAD` against the target head. When they differ, run `{{PANCREATOR_PAN_COMMAND}} worktree create <name> --from <target-head> --json`, or resolve an existing worktree already at that commit, and use the reported path as the review workspace. Name that path to the operator and to the coordinator. When the operator named a worktree on the command, add `--worktree <name>` in step 2 so the card binds the session to it, and confirm it sits at the target head.
6. Run `{{PANCREATOR_PAN_COMMAND}} governance review-scope --target <target-head> [--base <base>] --json` and read `conflicts`. A non-empty list means the target edits the review machinery itself, so the squad would be grading the instrument it is holding. Exclude those paths from the squad's verdict, delegate one `pan-reviewer` subagent over just those paths for an independent read, and carry both results into the final report. `independent: true` means the squad covers the whole target and no second reviewer is needed.
7. Write a short intent brief from the target's own evidence: the commit subjects in the range, the request file, and any linked card or acceptance criteria the operator named. Say plainly when no stated intent exists — the coordinator needs to know that a finding cannot be dropped as "already answered".
8. Delegate exactly one `pan-shepherd-reviewer` subagent in **resolve** mode with the captured diff path, the review workspace path, the intent brief, the resolved target, and any review-machinery paths step 6 excluded. It returns the lineup, each charter verbatim, the finding shape, and the exclusions, and edits nothing. Its model comes from the `shepherd-reviewer` mapping in `config.json`.
9. Issue the dimension fan-out yourself, at the top level and in one message: one ad-hoc subagent per charter the coordinator returned, each carrying the capture path, the workspace path, the intent brief, its charter verbatim, the finding shape, and the exclusions. Omit `model` so each inherits this session's model. A dimension agent spawned by the coordinator would be a nested spawn and run on the platform default model, which is why the fan-out is yours. Collect each agent's raw findings without judging them.
10. Delegate the same `pan-shepherd-reviewer` again in **join** mode with the raw finding files. It merges duplicates, drops what the intent brief answers with each reason recorded, ranks, and returns the finding set with a pass or fail verdict. Do not join, rank, drop, or grade a finding yourself.
11. Do not edit, stage, commit, push, or write workflow state at any point, and do not act on a finding. When the operator wants a finding fixed, that is a separate `/pan-spotfix` or a systematic run.

Include the resolved target, the capture path, the review workspace path, any review-machinery paths the squad could not grade and what the independent reviewer said about them, the dimensions that ran, the dimensions that returned nothing, and the verdict. Do not rewrite or summarize it outside the block.
