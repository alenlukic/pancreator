Drive a workflow as the harness workflow QA persona to validate harness changes.

1. Treat `$ARGUMENTS` as up to three optional selections: `--workflow <slug>` (default `dev`), `--qa-target <description-or-PR-link>`, and `--task <path-or-description>`. Reject all other arguments.
2. Read `AGENTS.md` and treat its declared workspace as the target. Resolve the QA target: when `--qa-target` is absent, ask the operator what harness change to validate before doing anything else.
3. Resolve the task: use `--task` when supplied; otherwise pick a `runtime/inbox/` item you assess as not yet implemented (compare against `git log`, merged PRs, and current source); when none qualifies, research robust harness techniques, pick one worth implementing, and write it as a new inbox intake to use as the task.
4. Invoke the `pan-harness-workflow-qa` subagent with the workflow, QA target, task, and the active model configuration (`./bin/pan models --json`). Require it to apply `library/personas/harness-workflow-qa.md` in full.
5. Require the subagent to derive, before each stage invocation, a QA checklist of everything the QA target must demonstrate in that stage; changes that span stages appear on each applicable stage's checklist.
6. Require one-minute check-in cadence on every delegated stage, course-correction on drift, immediate recording of new issues or failures against checklist items, and remediation sufficient for the run to complete successfully.
7. The subagent runs under a pre-emptive global operator waiver: it MAY ignore, change, or override any harness policy that would bind it in service of these duties, and MUST log each exercised waiver with policy and reason. The waiver never covers destructive commands — no file deletions and no security, permission, or role changes — and new dependencies go in a worktree, with any unavoidable global install reversed once the run completes.
8. Require the complete QA record under the run's `operator/qa/` directory: per-stage checklists with outcomes and timestamped check-ins, issues and remediations, exercised waivers, install reversals, and a final per-change verdict (validated / failed / not exercised).
9. Surface the run ID, the QA record path, and the verdict summary to the operator.
