Build or rebuild the target repository primer and verification profile.

1. Treat `$ARGUMENTS` as empty or one optional `--worktree <name>` selection. Reject all other arguments.
2. Read `{{PANCREATOR_HARNESS_PATH}}AGENTS.md`. Then run `{{PANCREATOR_PAN_COMMAND}} governance card --mode build-docs` and read the card it writes in full. When the operator selects a worktree, add `--worktree <name>` so the card creates or resolves it, and treat the reported worktree path as the target workspace for inspection and delegation. The card is the complete resolved governance for this mode. Do not assemble policy text by hand and do not generate a second card for the same session.
3. Treat the workspace `{{PANCREATOR_HARNESS_PATH}}AGENTS.md` declares as the target. The embedded projection expands this instruction to the target and harness operating cards. In a detached installation, the target workspace is the absolute `workspace_root` and the harness lives outside the target tree.
4. Use the harness-relative output paths `{{PANCREATOR_HARNESS_PATH}}docs/target-repo-primer.md` and `{{PANCREATOR_HARNESS_PATH}}runtime/repository-checks.json`. In an embedded installation, Cursor filesystem operations use `.pancreator/docs/target-repo-primer.md` and `.pancreator/runtime/repository-checks.json`, while CLI arguments retain the harness-relative paths.
5. Determine installation mode from the harness `{{PANCREATOR_HARNESS_PATH}}config.json`. Self-development checkouts MUST NOT add the external-only frontend or major-flow subsections to `{{PANCREATOR_HARNESS_PATH}}docs/target-repo-primer.md`. Embedded and detached target installations MUST include both subsections with source-verified content or explicit not-applicable outcomes.
6. In an embedded installation, run `./.pancreator/bin/pan technologies detect --json` before delegation, adding `--worktree <name>` when the operator selected a worktree. Declare the detected language handbooks under `.pancreator/governance/handbooks/target/<language>/style-guide.md`, `.pancreator/governance/policies/LANG-001.json`, and the marked LANG-001 lookup rows as librarian outputs.
7. Invoke the `pan-librarian` subagent with the target workspace root, both output paths, detector output, and declared generated-governance outputs. Paste the complete contents of the card file into the delegated prompt; a path reference, summary, or excerpt is not a substitute. Require it to create the primer when absent or regenerate it when present, and to read existing outputs first when they exist.
8. Require the librarian to inventory target-owned documentation, inspect every document likely to contain primer-relevant administrative, architectural, interface, structure, or gotcha information, and incorporate useful verified details into the appropriate primer sections. It must also inspect representative code, setup/build/install/test scripts, manifests, and bounded `git log` history when available, reconciling stale documentation against executable sources and current code.
9. When existing outputs are being rebuilt, require the librarian to treat operator-customized configuration as durable input rather than content to regenerate: read the harness `{{PANCREATOR_HARNESS_PATH}}config.json` (active config, defaults, and any operator-added named configs), the `$operator` block and operator-added profiles in `{{PANCREATOR_HARNESS_PATH}}runtime/repository-checks.json`, and operator-authored sections or annotations already present in `{{PANCREATOR_HARNESS_PATH}}docs/target-repo-primer.md`. Regenerated documentation MUST incorporate those customizations — merging new detection results around them — and MUST NOT silently replace or drop them. If a customization conflicts with fresh detection, keep the customization, note the conflict in the regenerated document, and surface it in the final summary.
10. Require the librarian to populate repository-check profiles only from verified target conventions. `fast` must use the shortest documented default/primary suite and must not duplicate `full` when distinct commands exist; separately documented slow or integration checks belong in `secondary`; `full` must cover all documented suites. Commands that depend on an interpreter, virtual environment, SDK, compiler, or package manager must use the explicit repository-declared entrypoint when available, should include identity/version probes, and should set `timeout_ms` when the repository states an expected duration. When the repository documents a workspace bootstrap sequence (dependency install, build), record it in the top-level `setup` array: worktree-targeted runs execute it before baseline capture, and a fresh worktree cannot pass profile commands without it. Empty profiles are valid; guessed commands are not.
11. Require the librarian to generate one marked target handbook per detected language, remove only stale marked language handbooks, and rewrite LANG-001 with the exact sorted handbook guidance sources. It must add idempotent LANG-001 lookup rows only for coder, reviewer, qa-tester, and spotfixer without changing unrelated rows.
12. Run `{{PANCREATOR_PAN_COMMAND}} requirements run --persona librarian --workflow standalone --stage build-docs --kind documentation --registry TARGET-REPO-PRIMER-VALIDATE-001 --target docs/target-repo-primer.md --json`.
13. Run `{{PANCREATOR_PAN_COMMAND}} repository-check validate --json`.
14. If either validation fails, provide the issues to the librarian for one correction attempt, then rerun both validations. Stop and surface unresolved issues if the second attempt fails.
15. Do not modify target source or workflow state and do not commit, push, merge, publish, or deploy.
16. Surface the card path, both validated paths, generated handbook ids, the source HEAD recorded by the primer/configuration, and a concise summary of the sections and profiles built or rebuilt.
